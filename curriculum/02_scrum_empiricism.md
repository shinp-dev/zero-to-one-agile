# 第2章：Scrumと経験主義

## ゴール

**AgileとScrumを区別し、Scrumの透明性・検査・適応を説明できる。**

## AgileとScrumは同じではない

```text
Agile
= 価値観・考え方

Scrum
= 複雑な問題に対して価値を生み出すための軽量なframework
```

ScrumはAgileの価値観と相性のよい代表的なフレームワークですが、Agile = Scrumではありません。

## なぜ短いSprintを回すのか

未来を完全に予測できない仕事では、最初の計画だけで正解へ到達するのが難しくなります。

Scrumは経験主義に基づきます。

```text
やってみる
 ↓
結果を見る
 ↓
学ぶ
 ↓
調整する
```

## 3本柱

### Transparency — 透明性

判断に必要な状態が見えること。

例：
- 今何を目指しているか
- 何がDoneか
- 何が詰まっているか
- Product Backlogの順序はどうなっているか

### Inspection — 検査

成果やゴールへの進捗を頻繁に確認すること。

「監視して責める」ではなく、**現実と仮説の差を見つける**ための検査です。

### Adaptation — 適応

検査で新しいことが分かったら、できるだけ早く調整すること。

```text
検査した
でも計画は絶対変えない
```

ではScrumのループが成立しません。

## 5つのScrum Values

- Commitment
- Focus
- Openness
- Respect
- Courage

単なる標語ではなく、透明性・検査・適応が機能するための行動基盤です。

例えば問題を隠すとTransparencyが下がり、正しいInspectionができず、Adaptationも遅れます。

## Scrumは意図的に「不完全」

Scrum Guideは、実装方法やチケットの書式まで指定しません。

だから現場では、

- User Story
- Story Point
- Kanban board
- CI/CD
- GitHub Flow

などを組み合わせます。

ただし、それらをScrumそのものと混同しないようにします。
